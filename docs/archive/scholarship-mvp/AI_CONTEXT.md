# AI 코딩 도구용 프로젝트 맥락

## 프로젝트 정체성

이 저장소는 렘넌트 장학사업의 신청, 심사, 선발, 지급, 사후관리 업무를 전산화하는 프로젝트입니다. 현재는 Python 3.13, FastAPI, SQLAlchemy, SQLite를 사용하는 백엔드 초기 구현 단계입니다.

## 우선 참고 문서

1. `README.md`: 프로젝트 전체 범위와 사용자
2. `REQUIREMENTS.md`: 기능 및 비기능 요구사항
3. `DATABASE.md`: 엔터티, 관계, 개인정보 규칙
4. `API.md`: API 경로와 권한 초안
5. `DEVELOPMENT.md`: 개발 규칙과 품질 기준
6. `TASKS.md`: 구현 순서와 진행 상태

## 도메인 용어

- **사업**: 장학사업의 큰 운영 단위
- **공고**: 특정 기간 동안 장학금 신청을 받는 모집 단위
- **신청자**: 공고에 신청한 사람
- **신청**: 신청자가 특정 공고에 제출하는 하나의 업무 건
- **심사**: 심사자가 신청 건을 기준에 따라 평가하는 과정
- **선발**: 심사 결과를 바탕으로 최종 대상자를 확정하는 과정
- **지급**: 선발자에게 장학금을 지급하고 결과를 기록하는 과정

## AI 작업 규칙

- 코드를 작성하기 전에 관련 요구사항, API, DB 문서를 먼저 확인한다.
- 기술 스택이 확정되지 않은 상태에서 프레임워크나 라이브러리를 임의로 추가하지 않는다.
- 개인정보, 계좌 정보, 첨부파일을 로그나 테스트 데이터에 원문으로 넣지 않는다.
- 상태 전이, 권한 검사, 감사 로그를 우회하는 구현을 제안하지 않는다.
- 기존 문서와 코드의 용어를 유지하고, 용어가 바뀌면 관련 문서를 함께 갱신한다.
- 요구사항이 모호하면 추측해 확정하지 말고 `결정 필요 사항`으로 남긴다.
- 변경 전후에 관련 테스트와 문서의 일관성을 확인한다.
- 브라우저 인증 변경 시 쿠키 속성, 토큰 노출, 역할별 리다이렉트를 함께 검토한다.
- 사용자 요청 범위를 벗어난 리팩터링이나 실제 코드 생성은 하지 않는다.

## 구현 시 우선순위

1. 인증, 권한, 개인정보 보호
2. 상태 전이와 데이터 무결성
3. 신청 및 심사 핵심 업무
4. 선발, 지급, 통지
5. 통계와 운영 편의 기능

## 현재 기술 스택

- Python 3.13
- FastAPI
- SQLAlchemy 2.x
- SQLite 로컬 개발 DB
- JWT와 bcrypt 기반 인증
- 브라우저 로그인은 `access_token` 쿠키를 사용하며 API Bearer 헤더도 계속 지원
- 프로그램·공고 API는 `/api` 접두사 사용
- 프론트엔드는 아직 구현하지 않음

## 현재 확정되지 않은 사항

- 운영 DBMS와 파일 저장소
- 운영용 JWT 비밀키 관리 및 외부 본인확인 방식
- 알림 채널과 지급 연동 방식
- 세부 심사 기준, 승인 단계, 개인정보 보존 기간

## AI 인수인계 규칙

- 작업 시작 시 `AI_PROGRESS.md`, `TASKS.md`, `REQUIREMENTS.md`, `DATABASE.md`, `API.md`를 먼저 확인한다.
- feature 단위 작업은 관련 코드·검증·문서를 한 묶음으로 완료하고 커밋한다.
- 기능을 완료했다고 보고하기 전에 재현 가능한 검증 명령과 결과를 `AI_PROGRESS.md`에 기록한다.
- 오류가 발생하면 증상, 재현 명령, 원인, 수정, 재검증 결과를 `AI_PROGRESS.md`의 트러블슈팅 로그에 남긴다.
- 기존 커밋되지 않은 사용자 변경은 덮어쓰거나 되돌리지 않는다.
- 비밀키, 토큰, 개인정보, 운영 DB 파일은 문서와 로그에 기록하지 않는다.
